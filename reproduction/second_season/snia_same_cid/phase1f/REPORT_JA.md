# Phase 1F 報告書：異系列の公開入力依存監査

## 結論

Phase 1F は、固定済みの69行・30同一CID群・48組について監査を完了した。
公開リリースから、候補測光入力、実際に使用されたフィルタ、公開較正定義、
および有効なパイプライン設定を分類できた。一方、特定の公開候補が特定の
最終カタログ行を生成したことを示す実行マニフェストやハッシュ連鎖は公開物に
なく、最終 `m_b_corr` 行への直接祖先は未証明である。

48組の主比較では、バイト完全一致の公開 `OBS:` 行を含む組は0、4量の
測光ペイロードが丸め精度の範囲で相互一意に1件だけ適合した組は4、2件以上
適合した組は0だった。4件はいずれもフィルタ記号、公開透過曲線blob、KCOR
フィルタ定義が一致しなかった。MJD差が0.11日以下だったのは1件だけであり、
この時間幅は限定例を見た後に設定された記述量にすぎない。

正式な科学分類は次のとおりである。

`PUBLIC_INPUT_DEPENDENCIES_CLASSIFIED_REPEATED_PAYLOAD_PAIRS_0_OF_48_SINGLE_PAYLOAD_PAIRS_4_OF_48_FILTER_RECORDS_MAPPED_434_OF_434_CONFIG_SERIES_PASS_7_OF_7`

## 問いと範囲

先行段階で固定された同一CID行について、固定公開リリースから次をどこまで
確立できるかを調べた。

- 公開測光記録の共有または相違
- 観測フィルタと公開較正定義
- light-curve fitting の設定入力
- 下流集約設定

母集団は、修正版Phase 1Dから38候補、修正版Phase 1Eから31候補、合計69候補
である。これらは30の同一CID群と48の群内非順序対を作る。ただし各候補は
「固定された公開入力候補」であり、最終測定値の実行済み祖先として扱って
いない。修正版Phase 1DとPhase 1Eの分類はハッシュ固定し、変更していない。

## 情報源と時系列

公開情報源は Pantheon+SH0ES DataRelease のコミット
`c447f0fea703fcd0fff57de5000947b5ca81286b` に固定した。45ファイルと20 Git
treeを固定し、測光・較正・SALT2の主要tree OIDも記録した。

主契約は69ファイル全件と48組全件の走査前にプロジェクト内部でハッシュ固定
した。ただし公開事前登録ではなく、完全盲検でもない。SN 2009cz、SN 2007qe、
SN 2009Dの限定例と、SN 2007qeの類似ペイロード値は既に見えていた。交差CID
診断は主結果を見た後に設計して別途固定した事後解析であり、主解析の事前性を
遡及的に強めるものではない。

## 方法

### 候補と測光ファイル

各候補について、固定コミットで追跡されたblobであること、各ディレクトリの
`.LIST` / `.IGNORE` 規則で有効であること、期待CIDと一致することを要求した。
パーサは `SNID`、`SURVEY`、`VARLIST`、`NOBS` を検証し、`MJD`、`FLT`、
`FLUXCAL`、`FLUXCALERR`、`MAG`、`MAGERR` を必須とした。69個の異なる
候補blobから6,744観測行を読み取った。

残差、fit後パラメータ、共分散、赤方偏移、H0、最終 `m_b_corr` は候補選択にも
対比較にも使用していない。

### 対比較

最強の一致試験は、文字列 `OBS:` の後ろの生バイト完全一致である。主たる
許容比較では、表示された各10進数を最小表示桁の半分を幅とする閉区間に変換し、
`FLUXCAL`、`FLUXCALERR`、`MAG`、`MAGERR` の4量すべてで区間が重なることを
要求した。MJDとフィルタ記号はエッジ定義に使わず、両端で次数1となる相互一意
エッジだけを採用した。

これは公開された数値ペイロードの互換的一致を検出する規則であり、
ペイロードの再利用そのものを確立する規則ではない。同一の生画像、物理的露光、
因果的共分散、統計的依存も確立しない。機械可読台帳に残る凍結済みlayer token
`PUBLISHED_PHOTOMETRIC_PAYLOAD_REUSE` は再現性のため保持した旧称であり、
読者向けには「公開測光ペイロードの互換性」と解釈する。

### フィルタ・較正・設定

各候補で実際に使われた生のフィルタ記号について、固定KCORテキスト内の
大文字小文字を区別した一意な `FILTER:` 定義と、その定義が指す公開透過曲線
assetを要求した。434件の「行×使用フィルタ」は6,744観測すべてを覆い、5個の
KCOR入力と50個の異なる公開透過曲線blobへ対応した。

Phase 1F候補が0行だった1系列も含め、`PPLUS.yml` 上の7系列を監査した。
DATAPREP、LCFIT、KCOR alias、共通入力、`REALDATABS20NOM` 集約の固定anchorは
7/7で合格した。これは設定レベルの証拠であり、job log、run manifest、FITRES
由来連鎖、実行同一性の証明ではない。

## 公開assetの所在

設定が参照する16件を分類した。`ALL.fitopts`、6個のheader override、
`SALT2.INFO`（公開モデル10候補）の8件は、実行同一性を伴わない公開basename
候補があった。7個のbase NMLと `SALT2muH0_data_foranthony.input` の8件は、
固定リリース内に同basenameがなかった。いずれの分類も、外部パスの特定byteが
最終実行で使われたことを証明しない。

## 事後の交差CID衝突診断

主48組に現れたsource-directory対と同じ層に限り、交差CIDの全候補ファイル対を
同じ丸め適合規則で調べた。

| 量 | 件数 |
|---|---:|
| 交差CID候補ファイル対 | 1,523 |
| 観測対の機会数 | 14,670,999 |
| 陽性ファイル対 | 24 |
| 相互一意の適合件数 | 24 |
| directory対の層 | 11 |

陽性は主解析の4陽性を含む3つのdirectory対層に現れた。ただし候補群と観測は
交換可能ではなく、p値は計算していない。したがってこれは記述的衝突screenで
あり、較正済み帰無分布や因果試験ではない。保護された主結果は診断の前後で
バイト完全一致した。

## 解釈と停止点

公開リリースから、69候補が異なる公開ファイルであること、固定規則の下で4件の
孤立した系列横断ペイロード一致があること、全使用フィルタが公開KCOR定義と
透過曲線へ対応すること、7系列すべてが有効な共通設定・集約graphに現れることは
言える。

一方、各一致が同じ物理的露光であること、同一CID行が統計的に独立または依存で
あること、候補が特定の最終 `m_b_corr` 行を生成したことは言えない。よって
Phase 1Fは、再fit、行の削除・統合・再重み付け、共分散変更、修正H0、tension
有意度更新、因果説明、新物理の主張を行わずに停止する。
